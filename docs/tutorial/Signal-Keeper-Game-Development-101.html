Game Development 101
Learn by editing Signal Keeper

A practical introduction for adult beginners. Follow four small changes to understand how a menu, game rules, interface, and music work together.

01 · Create a menu02 · Code the playing mechanism03 · Update the UI04 · Add background music

Before you start · 5 minutes

  1. Make a learning copy of D:\Signal Keeper, so you can experiment safely.
  2. Open Godot → Import → select the copy’s project.godot.
  3. Open main.tscn, then double-click main.gd in the FileSystem panel. Press F6 to run the current scene, or F5 to run the project.
  4. Use Ctrl+F in the script editor to find each function named in this guide. Stop the game, save your edit, and run again.

Project map: main.tscn is the main scene. main.gd holds the rules, drawing, buttons, and audio. pixelart/ contains images; audio/ contains sound.

In this project, most interface elements are created or drawn in code, so you will not find every button in the scene tree before running it. Screenshots below are from the actual desktop game, captured 8 October 2026. Yellow boxes are teaching annotations.

SIGNAL KEEPER / GAME DEVELOPMENT 101

01 / Create a menu

A button needs a label, a position, and an action.

Where to edit

In main.gd, find _ready() for button creation, make_button() for shared styling, and draw_menu_screen() for the title and progress panel.

A state tells the game which screen is active: MENU, GAME, or SETTINGS.

How the existing Play button works

menu_play_button = make_button(
    Vector2(40, 420), "PLAY  /  RESTORE RELAYS",
    on_play_pressed, 400, 58
)

Vector2(40, 420) means 40 pixels from the left and 420 from the top. The final two values are width and height.

func on_play_pressed() -> void:
    current_state = State.GAME
    update_buttons()
    queue_redraw()

Short excerpt: the actual function also resumes music. Inside make_button(), button.pressed.connect(action) connects the click to its function.

Try it: change only the Play label to START MISSION. Keep the existing callback.

Check: the new label appears and clicking it opens the puzzle. Settings still opens the audio screen.

02 / Code the playing mechanism

Input → change the puzzle → check the result → redraw.

Where to edit

Find rotate_at(), connections(), powered_cells(), and is_solved() in main.gd.

When you tap a relay, the game finds its grid cell, rotates it, spends a move, and checks whether electricity can reach the target.

relay.r = posmod(relay.r + 1, 4)
moves += 1

# The win condition:
func is_solved() -> bool:
    return receiver in powered_cells()

Rotation cycles through 0 → 1 → 2 → 3 → 0. A connection counts only when both neighbouring relay ports face each other. Visually touching sprites alone does not create a connection.

Change difficulty without breaking the rules

Find MOVE_ALLOWANCES near the top. Its ten entries provide extra moves for the ten sectors. reset_board() calculates:

move_limit = par_moves + MOVE_ALLOWANCES[level - 1]
Try it: change the first allowance from 2 to 4. Sector 1 now starts with 8 moves instead of 6.

Check: a valid relay tap spends exactly one move; tapping an empty cell spends none. Connecting the target completes the sector.

For later practice: LEVEL_PATHS defines routes. Keep consecutive cells adjacent, and keep the source’s right port and target’s left port compatible with the route.

03 / Update the UI

The UI explains the game’s state to the player.

Where to edit

  • draw_game_screen(): title, moves, timer, grid, and result messages.
  • make_button(): button colours, borders, corners, and text size.
  • COLS, ROWS, CELL, ORIGIN: grid dimensions and position.
  • project.godot: viewport and scaling configuration.

HUD means heads-up display: the information visible while you play. Changing its appearance should not change the rules.

const CELL := 72.0
const ORIGIN := Vector2(24, 234)
const CYAN := Color("55e7ff")

This project uses a 480 × 800 portrait canvas. Six 72-pixel columns take 432 pixels, leaving 24 pixels on each side. Changing the cell size may require moving other elements too.

Try it: change CYAN to Color("8ce8c3"), then change the instruction text in draw_game_screen() to Rotate relays. Reach the target.

Check: text stays inside the portrait window, all six columns fit, buttons remain readable, and relay taps still select the correct cell.

Godot settings: Project → Project Settings → Display → Window. This game uses canvas_items stretching and keeps its aspect ratio; wider screens may have unused space.

04 / Add background music

Load a sound file, attach a player, loop it, and let the player control volume.

Where to edit

Find the # Audio setup block in _ready(). The current track is audio/bgm_timelapse.mp3: Timelapse Background by Verclub_Music.

bgm_player = AudioStreamPlayer.new()
var bgm_res: AudioStreamMP3 = preload(
    "res://audio/bgm_timelapse.mp3"
)
bgm_res.loop = true
bgm_player.stream = bgm_res
add_child(bgm_player)

Later in _ready(), bgm_player.play() starts playback. res:// means the project folder. user:// is the writable folder used for saved preferences.

Try it: put a licensed MP3 in audio/, let Godot import it, and change the preload path to your file. Keep the loop setting and the existing player.

Use set_music_volume() for volume. save_settings() and load_settings() remember the choice. Avoid adding a second music player, which would play two tracks at once.

Check: music plays in the menu and during gameplay, the −/+ controls work, 0% mutes it, and your chosen volume survives a restart.

No sound? Check the saved music level first—the screenshot shows 10%—then system volume, the file path, and Godot’s error output. Keep source and permission records in audio/MUSIC_CREDITS.md.

FINAL PRACTICE / 10 MINUTES

Make one small version of your own

Rename the Play button, give Sector 1 two extra moves, choose an accent colour, and replace the music with a track you have permission to use.

  1. Change one thing.
  2. Save and run the game.
  3. Check the expected result.
  4. If something breaks, undo the last change and read the first error.

Explain your work to a classmate

“This button calls this function. This function changes the game state. This drawing code displays that state. This audio player supplies the soundtrack.”

That is the core workflow: input, rules, feedback, and iteration.
